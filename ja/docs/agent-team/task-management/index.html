タスク管理

タスク管理は、Alius Agent Teamのコア機能の1つです。効率的なタスク割り当てと追跡メカニズムにより、複数のエージェントの協調能力を十分に活用して、複雑なワークフローを完了できます。

タスクの概念

タスクとは

Alius Agent Teamでは、**タスク（Task）**は、エージェントに実行を割り当てられた作業単位です。タスクは、簡単な質問、複雑なマルチステッププロセス、または長時間実行されるバックグラウンドジョブになります。

タスクタイプ

システムは、複数のタスクタイプをサポート：

タイプ説明例
即時タスク即時実行”Pythonコードを書いてください”
スケジュールタスク指定時間に実行”毎日午前9時に昨日のレポートを生成”
繰り返しタスク設定された間隔で繰り返し実行”1時間ごとにサーバーステータスを確認”
依存タスク他のタスク完了後に実行”データ処理完了後、可視化レポートを生成”
バッチタスク類似する複数のタスクをバッチ処理”これらの100枚の画像の説明を生成”

タスクの作成

インターフェースからタスクを作成

ステップ1：ターゲットエージェントを選択

以下の方法でエージェントを選択可能：

  • エージェントリストから直接選択
  • システムに最適なエージェントを自動選択させる
  • タスク作成後にエージェントを割り当て

ステップ2：タスク情報を入力

  • タイトル：タスクの短い説明（必須）
  • 説明：タスク要件の詳細説明（必須）
  • 優先度：タスク優先度を設定
    • 緊急：即座に処理が必要
    • 高：重要かつ時間に敏感
    • 中：通常優先度
    • 低：緊急でないタスク
  • 期限：タスク完了期限を設定（オプション）
  • タグ：分類と検索のためにタスクにタグを追加

ステップ3：高度なオプション設定

  • コンテキストファイル：タスクコンテキストとして関連ファイルをアップロード
  • 出力形式：出力形式要件を指定
  • コールバックURL：タスク完了時に通知するURL
  • タイムアウト設定：タスク実行タイムアウトを設定

ステップ4：タスクを送信

「送信」ボタンをクリックすると、タスクは選択されたエージェントに送信されます。

API経由でタスクを作成

curl -X POST https://api.alius.ai/v1/tasks \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "コードレビュー",
    "description": "以下のPull Requestのコード品質をレビュー",
    "agentId": "agent_12345",
    "priority": "high",
    "deadline": "2024-01-20T17:00:00Z",
    "attachments": [
      {
        "type": "url",
        "url": "https://github.com/example/repo/pull/123"
      }
    ]
  }'

バッチでタスクを作成

複数の類似タスクを作成する必要がある場合、バッチ作成機能を使用可能：

  1. タスク情報を含むCSVまたはJSONファイルを準備
  2. タスクリストページで、「バッチ操作」 > 「タスクインポート」をクリック
  3. ファイルをアップロードしてフィールドをマッピング
  4. インポートを確認

バッチタスクファイル例（JSON）：

[
  {
    "title": "データファイル1を分析",
    "description": "data1.csvのデータ分布を分析",
    "agentId": "agent_12345"
  },
  {
    "title": "データファイル2を分析",
    "description": "data2.csvのデータ分布を分析",
    "agentId": "agent_12345"
  }
]

タスク割り当て

自動割り当て

Alius Agent Teamは、インテリジェントなタスク割り当てを提供：

負荷分散割り当て

システムは、以下の要因に基づいて最適なエージェントを自動選択：

  • エージェントの現在の負荷
  • エージェントタイプと能力のマッチ度
  • エージェントの過去のパフォーマンス
  • タスクの優先度と要件

ルールベース割り当て

割り当てルールを設定可能：

ルール1：コード生成タスク -> 「codegen」タグのエージェントに割り当て
ルール2：高優先度タスク -> 負荷が50%未満のエージェントに割り当て
ルール3：ビッグデータタスク -> メモリが4GB以上のエージェントに割り当て

手動割り当て

タスクを特定のエージェントに手動で割り当て可能：

  1. タスクリストで未割り当てのタスクを見つける
  2. 「割り当て」ボタンをクリック
  3. 利用可能なエージェントリストから選択
  4. 割り当てを確認

再割り当て

タスク割り当てが不適切な場合、再割り当て可能：

  1. 再割り当てするタスクを見つける
  2. 「その他の操作」 > 「再割り当て」をクリック
  3. 新しいエージェントを選択
  4. オプション：再割り当て理由を追加
  5. 再割り当てを確認

タスク追跡

タスクステータス

タスクは、ライフサイクル中に以下のステータスを経験：

保留中 (Pending)
    ↓
実行中 (Running)
    ↓
    ├── 完了 (Completed)
    ├── 失敗 (Failed)
    └── キャンセル (Cancelled)

ステータスの説明

  • 保留中：タスク作成済み、エージェント受信待ち
  • 実行中：エージェントがタスクを実行中
  • 完了：タスクが正常に完了
  • 失敗：タスク実行が失敗
  • キャンセル：ユーザーによってタスクがキャンセル

リアルタイム進捗追跡

進捗インジケーター

長時間実行されるタスクの場合、システムはリアルタイム進捗更新を提供：

[=======>     ] 65% - ファイル13/20を処理中
残り時間：約2分

タスクログ

タスクの詳細な実行ログを閲覧：

  1. タスクをクリックして詳細を閲覧
  2. 「実行ログ」タブを選択
  3. リアルタイムまたは履歴ログを閲覧
[ステップ1/3] 入力ファイルを読み込み中... ✓ 完了 (12ms)
[ステップ2/3] データを分析中... ▶ 実行中 (45%)
[ステップ3/3] レポートを生成中... ○ 待機中

タスク詳細閲覧

任意のタスクをクリックして、完全な詳細を閲覧：

  • 基本情報：タイトル、説明、ステータス、優先度など
  • 割り当て情報：どのエージェントに割り当てられたか、割り当て時間
  • タイムライン：タスク作成、割り当て、開始、完了の時間
  • 実行結果：タスク出力、生成ファイル、エラー情報など
  • 履歴：タスクのすべてのステータス変更履歴

タスクスケジュール

スケジュールタスク

特定の時間に実行されるタスクを作成：

  1. 新しいタスクを作成する際、「スケジュール実行」を選択
  2. 実行時間を設定
  3. オプション：実行後に繰り返すかを設定

例：

実行時間：2024-01-20 09:00:00
繰り返し：繰り返さない

繰り返しタスク

間隔を設定して繰り返し実行されるタスクを作成：

  1. 新しいタスクを作成する際、「繰り返し実行」を選択
  2. 繰り返しルールを設定：
    • 分単位：N分ごとに実行
    • 時間単位：N時間ごとに実行
    • 日単位：毎日1回実行
    • 週単位：毎週指定日実行
    • 月単位：毎月指定日実行
    • Cron式：標準Cron式を使用
  3. 必要に応じて終了日を設定
  4. タスクを作成

Cron式の例：

0 9 * * 1-5  # 月曜から金曜の午前9時に実行
0 */2 * * *   # 2時間ごとに実行
0 0 1 * *     # 毎月1日の深夜に実行

依存タスク

他のタスク結果に依存するタスクを作成：

  1. 新しいタスクを作成する際、「依存タスク」を選択
  2. 依存タスクを追加：
    • 前提タスク：完了する必要があるタスク
    • 条件：前提タスクの成功条件
  3. 依存関係を設定：
    • 順次実行：A完了後にBを実行
    • 並列実行：AとBの両方が完了した後にCを実行
    • 条件分岐：Aの結果に基づいてBまたはCを実行

タスク管理操作

タスクキュー管理

キューを閲覧

「タスク」ページで、以下を閲覧可能：

  • すべてのタスク：システム内のすべてのタスク
  • 自分のタスク：自分が作成したタスク
  • 保留中：割り当てまたは実行待ちのタスク
  • 実行中：現在実行中のタスク
  • 完了：正常に完了したタスク
  • 失敗：実行に失敗したタスク

キュー優先度調整

  1. 保留中タスクリストで、調整するタスクを見つける
  2. タスクを新しい位置にドラッグ（優先度の高いタスクが上）
  3. または、タスクの優先度フィールドを変更

タスク制御操作

タスクを一時停止

実行中のタスクを一時停止可能：

  1. 実行中のタスクを見つける
  2. 「一時停止」ボタンをクリック
  3. エージェントは実行を一時停止するが、現在の状態を保持
  4. 後で再開可能

タスクを再開

一時停止したタスクを再開：

  1. 一時停止したタスクを見つける
  2. 「再開」ボタンをクリック
  3. エージェントは一時停止した箇所から継続して実行

タスクをキャンセル

不要なタスクをキャンセル：

  1. キャンセルするタスクを見つける（ステータスは「保留中」または「実行中」である必要がある）
  2. 「キャンセル」ボタンをクリック
  3. キャンセルを確認
  4. タスクが実行中の場合、エージェントは実行を停止

タスクを再試行

失敗したタスクを再実行：

  1. 失敗したタスクを見つける
  2. 「再試行」ボタンをクリック
  3. オプション：タスクパラメータを変更
  4. タスクは保留中キューに再投入

タスクテンプレート

テンプレートを作成

頻繁に実行するタスクの場合、テンプレートとして保存可能：

  1. タスクを作成してすべてのパラメータを設定
  2. 「テンプレートとして保存」をクリック
  3. テンプレート名と説明を入力
  4. テンプレートはテンプレートライブラリに保存

テンプレートを使用

テンプレートから迅速にタスクを作成：

  1. タスク作成ページで、「テンプレートから作成」を選択
  2. テンプレートライブラリからテンプレートを選択
  3. 必要に応じてパラメータを調整
  4. タスクを送信

タスク分析とレポート

タスク統計

Alius Agent Teamは、豊富なタスク統計機能を提供：

概要統計

  • 総タスク数
  • 完了率
  • 平均完了時間
  • 失敗率

時間範囲統計

  • 今日のタスク量
  • 今週のタスク量
  • 今月のタスク量
  • カスタム時間範囲

エージェント次元統計

  • 各エージェントが完了したタスク数
  • 各エージェントの平均応答時間
  • 各エージェントのタスク成功率

レポートをエクスポート

タスクレポートを生成およびエクスポート：

  1. タスクリストページで、「エクスポート」をクリック
  2. エクスポート形式を選択：
    • CSV
    • Excel
    • PDF
    • JSON
  3. 含めるデータフィールドを選択
  4. 時間範囲を選択
  5. 「エクスポート」をクリック

ベストプラクティス

タスク分解推奨事項

複雑なワークフローの場合、複数の小さなタスクに分解することを推奨：

推奨されない：

タスク：eコマースウェブサイトを構築
（大きすぎて、追跡とデバッグが困難）

推奨：

タスク1：データベーススキーマを設計
タスク2：ユーザー認証モジュールを実装
タスク3：商品管理モジュールを実装
タスク4：注文処理モジュールを実装
タスク5：決済統合を実装
...

優先度設定推奨事項

  • 緊急：本番環境の障害、セキュリティ脆弱性など
  • 高：複数のチームに影響する重要な機能
  • 中：通常の機能開発と最適化
  • 低：実験的な機能と最適化提案

タイムアウト設定推奨事項

  • 簡単な照会タスク：30秒 - 1分
  • コード生成タスク：5 - 10分
  • データ処理タスク：30分 - 2時間
  • バッチ処理タスク：データ量に基づいて設定

トラブルシューティング

タスクが長時間「保留中」ステータスのまま

考えられる原因：

  • 利用可能なエージェントがない
  • エージェントの負荷が高すぎる
  • タスク優先度が低すぎる

解決方法：

  1. エージェントステータスを確認
  2. エージェント数を増加させるかタスク優先度を引き上げ
  3. 割り当てルールが正しいか確認

タスク実行が失敗

考えられる原因：

  • エージェントエラー
  • タスクパラメータが不正
  • 依存サービスが利用不可
  • タイムアウト

解決方法：

  1. タスク実行ログを閲覧
  2. タスクパラメータが正しいか確認
  3. 依存サービスのステータスを確認
  4. タイムアウト時間を増加

タスク結果が期待通りでない

考えられる原因：

  • タスク説明が十分に明確でない
  • エージェント設定が不適切
  • モデル選択が不適切

解決方法：

  1. タスク説明を最適化し、より明確な指示を提供
  2. エージェント設定を調整（例：温度パラメータ）
  3. 異なるモデルを試す
