What is Shell Gate?

Shell Gate is Alius’s human-in-the-loop security layer. Not every action should run autonomously — Shell Gate ensures you stay in control of sensitive operations.

How It Works

When the agent wants to execute a sensitive operation (shell commands, file writes, network requests), Shell Gate:

  1. Intercepts the operation
  2. Displays what will happen
  3. Asks for your explicit approval
  4. Logs your decision

Permission Levels

LevelBehavior
DenyAlways block this operation
AskRequire explicit approval each time
Auto-approveAllow without asking (use with caution)

Configuring Permissions

In .alius/config/permissions.toml:

[shell]
# Default policy for shell commands
default = "ask"

# Auto-approve safe read-only commands
auto_approve = ["ls", "cat", "git status", "git log", "git diff"]

# Always deny dangerous commands
deny = ["rm -rf /", "format", "mkfs"]

[file_write]
default = "ask"
deny_patterns = [".env", "credentials", "*.key"]

[network]
default = "ask"

Dangerous Operations

These operations are always blocked or require confirmation:

  • rm -rf with recursive directory deletion
  • Writing to files outside the workspace
  • Executing arbitrary downloaded scripts
  • Modifying git history (force push, etc.)

Audit Log

Every permission decision is logged with:

  • Timestamp
  • Operation type and details
  • Your decision (approved/denied)
  • Session and turn context

View the audit log through the trace system for any session.

Best Practices

  1. Start restrictive — Use ask as default for all operation types
  2. Add auto-approves gradually — Only for commands you run frequently and trust
  3. Review traces — Check the audit log periodically
  4. Never auto-approve writes — Keep file modifications requiring approval
